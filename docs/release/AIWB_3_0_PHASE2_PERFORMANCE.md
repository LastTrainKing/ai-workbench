## 为什么不编数

本轮唯一的源码改动是**新增一个测试工具**（`desktop-native/verify_projection.py`）与三份文档。
它不在产品的运行路径上，不改变任何页面、不增加任何请求、不进入安装包。

所以：

- **产品性能没有变化** —— 不是因为测了没变，而是因为**产品代码一行没改**。
- 因此"改前/改后"没有可对比的变量。

如果只为了填满表格去测一遍，得到的两个数字会是同一段代码的两次运行，噪声会被写进报告
当成结论。那比空着更糟。

---

## 下一轮需要测什么（以及怎么测才有意义）

一旦 P1 落地（那才是真正改变产品路径的改动），应当在同一台机器、同一数据量下测：

| 项 | 方法 |
|---|---|
| 首页数据加载 | `loadDashboard` 从发起到 `completed` 的墙钟时间 |
| 员工列表 / 合同展开 | 页面进入与 `contractOpen` 置位到渲染稳定的时间 |
| Artifact 列表与预览 | 列表请求 + 预览内容就绪的时间 |
| 冷启动 | 从快捷方式启动到 `startupState === "ready"` |
| 内存 / 打包体积 | 进程工作集；安装包字节数（已有：119.2 MB） |

**现有工具已能覆盖其中三项**：`ServiceBridge` 的 `completed` 信号给了前两项的现成测量点，
启动状态给了冷启动的测量点。不需要新设施。
