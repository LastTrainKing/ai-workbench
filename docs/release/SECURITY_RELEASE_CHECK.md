## 1. 核查范围

§4.2 明确要求**不能只扫当前工作树**。三处都扫了：

| 范围 | 方法 | 结果 |
|---|---|---|
| 当前工作树 | 已跟踪文件 + 未跟踪文件 | 干净 |
| 待提交 diff | `git diff` / `git diff --cached` | 空（工作区干净） |
| **全部 Git 历史** | `scripts/scan_git_history_secrets.py`（**本轮新增**） | **干净** |

原有扫描器 `build/rc/scan_for_secrets.py` 只走 `git ls-files` —— 已跟踪文件的**当前内容**。
这答不了 §4.2 真正要问的问题："有没有真实凭据**曾经**进过仓库"。一个密钥被提交、下一次提交
里删掉，当前树是干净的，而它仍躺在历史里，任何克隆的人都能拿到。

**当前树干净不等于仓库安全。**

## 2. 历史扫描（新增工具）

`scripts/scan_git_history_secrets.py`：


它遍历历史里的**每一个 blob**（`git rev-list --objects --all` → `git cat-file --batch`），

**结果：`[干净] 历史中没有任何本机真实凭据`。**

## 4. 本轮在扫描器自身发现并修掉的两个缺陷

**这两个都值得记下来，因为它们都是"工具说没问题，而它其实什么也没查"。**

### 4.1 扫描器扫了 0 个对象却报"干净"

第一版把 `_run()` 的 bytes 返回值套了 `str()` —— `str(b"a\nb")` 得到的是字面量 `b'a\nb'`
（转义的 `\n`，不是换行），按换行切分只得到一行，40 位 id 的过滤全部落空。

**结果是：`扫描 blob 数: 0` 而结论打印"历史与当前树均未发现真实凭据"。**

已修：返回值类型改为明确的 `str`，并加了一条自检 —— **扫到少于 10 个对象时中止并返回非 0，
而不是报"干净"**。一个什么都没测到的绿色结论，比没有结论更危险。

### 4.2 1406 处假阳性

第二版按"长串"（`[A-Za-z0-9_\-]{40,}`）从 `.env` 里捞凭据，捞到的是**注释分隔线** —— `.env`
里有一条 60 个连字符的分隔线，而源码注释里到处是同样的分隔线，于是报告 1406 处"真实凭据泄漏"。

已修：改成**按"这是什么"取值**而不是按"它长什么样" —— 只取键名匹配
`(KEY|SECRET|TOKEN|PASSWORD|CREDENTIAL)` 的键的值，空值跳过，长度不足 16 跳过。

**一个报 1406 个假阳性的扫描器和报 0 个的一样没用**：前者让人不再看结论，后者让人以为没问题。

## 5. 结论

| 检查项 | 结果 |
|---|---|
| 当前工作树含真实凭据 | **否** |
| 全部 Git 历史含真实凭据 | **否**（1877 个 blob / 63.5 MB 全扫） |
| 形状命中需人工复核 | 17 处，**全部为测试夹具**，逐条看过 |
| `.gitignore` 覆盖运行时文件 | **是** |
| `.env.example` 只含空值/占位符 | **是** |
| 需要轮换的凭据 | **无** |

**未发现需要轮换的凭据，不需要历史清理。**

### 仍需注意（不阻断发布，但要写进发布说明）

1. **测试夹具里的 `sk-…` 与 `AKIA…` 会持续触发扫描器告警。** 这是有意为之（它们必须长得像
   真凭据才能测出"不该接受"的行为），但会让每一次未来的扫描都需要人工复核。可以考虑加一个
   显式的夹具白名单，让真命中更突出。
2. **`build/rc/` 不在版本控制里**，而其中的秘密扫描器是旧的那一个（只扫当前树）。新的历史
   扫描器放在 `scripts/`（受版本控制），这是对的；版本三应当考虑把旧扫描器也纳入或删除，
   免得将来有人用了错的那个。
3. **`.env` 存在于开发机且含真实 Key** —— 它被正确忽略，但发布前应确认它从未被
   `git add -f` 之类的方式绕过。
