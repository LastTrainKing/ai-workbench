## 4.1 一条重要修正：§4 的前提不成立

§4 说这三个字段是"尚未暴露"的能力。**核对后不是。**

| 字段 | 实际情况 |
|---|---|
| `model_policy` | 全仓库**没有一处读它**；`"reasoning"` / `"fast"` 只出现在注释里，从未被当作路由键解析。模型仍是全局那一个。 |
| `memory_scope` | 没有任何代码按它过滤记忆。而且它声明的 `["global","user","project"]` 里，`user` **不是** `MemoryEntry.scope` 的合法值（`evaluator.py:321` 只产出 `global` / `project`）。 |
| `knowledge_scope` | 六个模板里都是 `{"knowledge_bases": [], "projects": []}`，恒为空。 |

所以它们是**声明了但没生效**，不是"没暴露"。把 `memory_scope` 画成一条边界，是在安全方向上
给假保证 —— 用户会认为存在一道并不存在的墙。§1（不捏造模型状态）与 §9（禁止用静态假数据回填）
都禁止这么做。

处理方式：**照实展示，但每一行都写"声明"，并在三节之后加一条警告说明尚未接入执行**；
`user` 这个词照实翻译并注明"记忆系统当前不使用这个词" —— 声明与实现对不上这件事本身值得
显示，不值得抹平。
