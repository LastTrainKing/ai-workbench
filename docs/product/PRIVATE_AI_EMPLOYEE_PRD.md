# 私人 AI 员工工作台：产品定义

版本 2.4.0 · 2026-10-13 · 依据 `docs/product/BASELINE_AUDIT.md` 与 `docs/product/OPEN_SOURCE_REUSE_AUDIT.md`

---

## 1. 产品定位

> 用户拥有一组可定制的私人 AI 员工。每个员工有明确的岗位、能力、工作习惯、长期记忆与权限，可以接受任务、按计划调用工具、执行实际工作、验证结果、交付文件，并在必要时向用户请求授权。所有重要数据优先保存在本地，用户能查看、修改、撤销和导出。

底层 Provider、Embedding、RAG 参数、任务队列、运行日志仍然存在，但属于「高级设置 / 技术详情」，不再是普通用户的第一层心智。

**本次改版的关键判断**：基线审计发现这个产品缺的不是引擎——记忆治理、权限分级、审批等待、工作区快照回滚、运行中断对账都已实现且有测试——而是**把已有引擎变成用户能理解和操作的东西**。所以本轮的重点是「员工」这一层实体，以及让已有能力可见的界面。

## 2. 产品原则（10 条）

1. **员工优先，而不是工具列表优先。** 用户先选员工或直接描述目标，系统内部再选模型、知识和工具。
2. **交付物优先，而不是对话轮数优先。** 任务最终指向文件、代码、分析或明确可验收的结果。
3. **本地优先，边界清楚。** 哪些数据只在本机、哪些发给模型服务商，用户能理解并能控制。
4. **员工有个性但不能胡作非为。** 人格可定制，但不能覆盖系统规则、权限、事实验证与安全要求。
5. **小而精的持久记忆。** 只记能减少重复沟通、提高正确率的信息；用户可查看、修改、删除、导出。
6. **真正持续工作。** 任务可后台运行、暂停、取消、等待授权、失败重试、重启恢复。
7. **显示依据与结果。** 展示步骤、调用过的工具、文件路径、验证结果和失败原因；不展示内部思维链。
8. **渐进暴露复杂度。** 新用户先看到「员工、任务、交付物、待确认」；工程参数放高级设置。
9. **默认不多智能体。** 一个任务先由单个员工完成。
10. **不承诺不验证的能力。** 没有的能力不用界面暗示。

### 2.1 原则在实现中的落点

| 原则 | 落在哪里 | 怎么验证 |
|---|---|---|
| 1 员工优先 | `employees` 表 + 岗位模板；导航新增「员工」分组 | `GET /api/v1/employees/templates` 返回 6 个岗位的完整合同 |
| 2 交付物优先 | 「交付物」页 + `deliverables` 表（含版本链与验证证据） | 界面上可打开、重新验证、接受、驳回 |
| 3 本地优先 | 本地 PostgreSQL / Redis / Qdrant；`ContextSnapshot` 记录每次注入了什么 | 「记忆」页的上下文预览回答「模型此刻会被告知什么」 |
| 4 人格不越权 | `persona_guard.py` 的检查；权限在执行端读取，不读提示词 | `POST /employees/persona/review` 对「你拥有完整权限」报出发现 |
| 5 小而精记忆 | `MemoryEntry` + `MemoryCandidate`（候选→用户确认）+ 清理计划先出后执行 | 「记忆」页的待确认队列 |
| 6 持续工作 | `RunState` 12 个状态，含 `WAITING_CONFIRMATION`、`INTERRUPTED` | 「待审批」页；`POST /agent/runs/{id}/reconcile` |
| 7 显示依据 | `tool_audit_log`（参数脱敏）、`Deliverable.verification` | 「运行记录」页 + 「交付物」页的验证证据 |
| 8 渐进暴露 | 导航分组：员工 / 工作区 / AI 工作 / 知识 / 计划 / 系统 | 见 §3 |
| 9 默认单员工 | 模板只给「空白岗位」一个只读工具集；没有多 Agent 编排 | 复用审计 §5 |
| 10 不暗示能力 | 模板的工具白名单在测试里对齐真实注册表 | `test_employee_layer.py::test_every_template_tool_exists_in_this_build` |

## 3. 信息架构

导航的实际结构（`desktop-native/qml/theme.js` 的 `navGroups`，唯一权威来源）：

```
工作区   工作台 · 项目 · 任务 · 文档 · 笔记
员工     我的员工 · 交付物                        ← 本次新增分组
AI 工作  对话 · Agent · 运行记录 · 待审批           ← 新增「待审批」
知识     知识库 · 问答 · 搜索 · 图谱 · 记忆          ← 新增「记忆」
计划     Planner
系统     权限 · 设置
```

19 个入口。**这不是任务书建议的 7 项结构**，是一个有意的折中：已有 15 个页面都在正常工作且有测试覆盖，删掉它们会把「看不见的功能」换成「没有的功能」。折中方式是新增「员工」分组并把它放在第二位，而不是把已有页面砍到 7 个。

**已知代价**：19 项在 800px 高的窗口里放不下，导航栏会滚动（1080px 下不需要）。滚动区底部有一条渐隐，让「还有更多」读起来是有意为之而不是被切坏。

## 4. 目标用户与场景

面向学习、研究、办公、创作、软件开发和日常个人项目。每个场景都基于**实际存在**的工具能力，不虚构集成。

| 场景 | 员工 | 用到的真实工具 |
|---|---|---|
| 学习与求知 | 研究员 / 知识管理员 | `knowledge_search`、`knowledge_document_read`、`file_read` |
| 研究与写作 | 研究员 | 同上 + `knowledge_link` |
| 办公 | 文档与演示专家 | `document_write`、`file_write`、`directory_create` |
| 软件开发 | 软件工程师 | `code_search`、`code_patch`、`run_tests`、`run_lint`、`run_typecheck`、`run_build` |
| 个人项目 | 通用助理 | `task_create`、`task_update`、`note_create`、`file_write` |

**没有的场景**（因为引擎没有对应能力，界面也不暗示）：邮件发送、日历连接、浏览器控制、桌面控制、IM 消息、云同步。

## 5. 首次启动

现状：`UserProfile.onboarded` 字段已存在，`GET/PATCH /api/v1/profile` 可用，`POST /api/v1/profile/extract` 能把一段自述解析成画像字段。**没有独立的引导页**——设置页承担了模型配置，画像通过接口维护。

这是本轮**未完成**的部分，如实记录：任务书 §5.2 要求的六步引导（本地优先说明 → 选模型接入 → 真实连接测试 → 选工作目录 → 偏好 → 创建第一位员工）中，第 2、3 步已有实现（`/ai-config` 8 个接口，含 `POST /ai-config/test` 真实连接测试），第 6 步已可用（「我的员工」页的招聘区），但没有把它们串成一个引导流程。

## 6. 任务闭环

复用已有的 `RunState` 状态机（12 个状态），映射到用户语言：

| 内部状态 | 用户看到的 |
|---|---|
| `PLANNING` / `READY` | 正在计划 |
| `EXECUTING` / `OBSERVING` | 执行中 |
| `VERIFYING` | 正在核对结果 |
| `RECOVERING` | 出错了，正在尝试修复 |
| `WAITING_CONFIRMATION` | **等你授权**（「待审批」页） |
| `PAUSED` / `CANCELLED` | 已暂停 / 已取消 |
| `FAILED` / `LIMIT_REACHED` | 失败（附原因） |
| `INTERRUPTED` | 进程中断，结果未知（可对账） |
| `COMPLETED` | 完成（附交付物） |

**闭环的八步与实现落点**：

| 步骤 | 实现 |
|---|---|
| 接单 | `POST /build-runs` 或对话；`DeliveryService.create_build_run` |
| 澄清 | `constraints.py` 的 `derive_constraints` / `resolve_preferences` |
| 规划 | `ExecutionPlan` / `PlanStep` |
| 执行 | `AutonomousAgent`（1619 行）+ 权限检查 + `tool_audit_log` |
| 质检 | `executor._verify_deliverables` + `Deliverable.verification` |
| 交付 | `deliverables` 表（路径、大小、版本、验证状态） |
| 复盘 | `skills` 的 `review` 接口（打分、退役） |
| 记忆更新 | `MemoryCandidate`（候选→用户确认→`MemoryEntry`） |

## 7. 非目标

明确不做，且不在界面上暗示：

- 多 Agent 协作与委派（任务书 §16：先确保单员工闭环可靠）
- 浏览器 / 桌面控制（任务书 §4.2 第 10 条）
- IM / 邮件 / 日历集成（§20 P3）
- 插件市场（现有 `ai/skills/` 的发现/导入/沙箱/复盘够用）
- 云端同步与多人协作
- 记忆的 Git 仓库（复用审计 §5 说明了理由）
