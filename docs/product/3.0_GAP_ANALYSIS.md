## 2. 已存在但用户不可见的能力（**本轮主战场**）

这是差距分析里最重要的一节。逐条带证据。

### 2.1 员工合同有 14 个字段，界面只显示 6 个

`ai/employees/templates.py:104-133` 定义：

```
mission / responsibilities / out_of_scope / inputs / sop / tools /
deliverable_kind / deliverable_location / acceptance / needs_approval /
prohibitions / definition_of_done / persona / knowledge_scope /
memory_scope / permission_profile / model_policy / avatar
```

`EmployeesPage.qml` 实际读到的：`name / mission / persona / role_id / summary / skills / tools /
status / archived / deliverable_kind / effective_narrowing / version / unknown_skills`

**用户看不到的**：`responsibilities`、`out_of_scope`、`inputs`、`sop`、`acceptance`、
`needs_approval`、`prohibitions`、`definition_of_done`、`knowledge_scope`、`memory_scope`、
`model_policy`、`avatar`。

任务书 §八 要的"岗位 / 使命 / 能力 / 工作方式 / 限制"，**除了使命，全都在数据库里，一个都没显示**。
`RoleTemplate.avatar` 字段甚至已经预留了图标位（模板里写着 `📚`/`💻`/`📊`/`📝`），界面没用。

### 2.2 记忆的 7 类 `kind` 与 `scope` 没有被展示

`ai/memory/evaluator.py:73`：`MEMORY_KINDS = ("identity", "goal", "preference", "skill",
"constraint", "fact", "decision")`；`models/context.py` 的 `MemoryEntry` 还有 `scope`（默认
`global`）、`confidence`、`source`、`status`。

`MemoryPage.qml` 只列条目与候选，**不显示分类、不显示置信度、不显示作用域**。

任务书 §十 要的"长期 / 项目 / 任务 / 临时"四分类，`scope` 字段**已经能承载**，只是没人用、没人看。

### 2.3 验证层存在，但只有两种检查

`services/delivery_service.py:203` 的 `verify_deliverable` + `models/delivery.py:295` 的
`make_verification` 已经在跑，实际产出的检查项只有：

```json
{"checks": [{"ok": true, "name": "file_exists", "detail": "1,358 bytes"},
            {"ok": true, "name": "readback",   "detail": "484 chars"}],
 "passed": true}
```

任务书 §九 要的按类型验收（文档查字数/格式、代码查编译/测试、PPT 查页数、数据查来源）
**一个都没有**。这不是"缺验证层"，是"验证层只有一个通用检查器"。

## 3. 当前用户流程断点

按任务书 §四 的闭环逐段核对：**需求 → 理解 → 规划 → 执行 → 验证 → 交付 → 反馈 → 学习**

| 段 | 现状 | 断在哪 |
|---|---|---|
| **需求** | 首页可输入 ✓ | **首页不能选员工** —— 点"交给员工执行"跳到 Agent 页才选。用户说了要做什么，还得在下一屏再决定谁来做 |
| **理解** | agent 有 `_resolve_requirements` | 用户看不到"它把你的话理解成了什么"。这是最该补的一环：误解在这里产生，也在唯一看不见的地方产生 |
| **规划** | plan 有，落库 | 只在专家模式可见（合理），但**普通模式一句"正在制定方案"都没有** |
| **执行** | 状态机完整 | 首页与交付物页仍显示英文枚举（`EXECUTING` / `COMPLETED`）。Agent 页已中文化（`buildRunWord`），**三处不一致** |
| **验证** | 只有 file_exists + readback | 见 §2.3 |
| **交付** | 交付物页有 打开 / 文件夹 / 继续修改 / 重新生成 | 缺**预览**（不打开外部程序也能看一眼）、缺质量分、缺"归档" |
| **反馈** | 接受 / 驳回（带理由） | 驳回理由落库（`feedback`），但**不进记忆**，员工下次还会犯 |
| **学习** | 记忆候选 + 审批 ✓ | 分类不可见、无上限、无"这条记忆来自哪次任务" |

**一句话概括**：闭环的每一段**都有后端实现**，断的都是**投影层**（把已有数据呈现给人）。

## 4. 本轮修改范围

按任务书优先级排列，每项标出落点。**全部是投影层与展示层改动，不动引擎。**

| # | 任务书 | 落点 | 性质 |
|---|---|---|---|
| 1 | §五 首页重构 | `qml/pages/DashboardPage.qml` | 加员工选择、中文状态、把"最近成果"提到主位 |
| 2 | §六 统一结果协议 | **新增** `services/task_result_service.py`（**读侧投影**） | 不改 Agent 输出，把 `build_runs` + `deliverables` + `verification` + `ai_runs` 合成一个 `TaskResult` |
| 3 | §七 成果中心 | `qml/pages/DeliverablesPage.qml` + 新桥接槽（预览 / 归档） | 补预览、质量分、归档 |
| 4 | §八 员工岗位展示 | `qml/pages/EmployeesPage.qml` | 把 §2.1 那 12 个不可见字段显示出来（**来自合同，不硬编码**） |
| 5 | §九 按类型验收 | `services/delivery_service.py` 的 `verify_deliverable` | 加类型化检查器（文档/代码/PPT/数据），**不降低现有标准** |
| 6 | §十 记忆分类 | `qml/pages/MemoryPage.qml` + 记忆写入侧 | 展示 `kind` / `scope` / `confidence`；把驳回理由接进记忆 |

### 关于 §六 的一个重要判断

任务书说"所有 Agent 最终必须转换为该结构"。**我建议实现为读侧投影，而不是改每个 agent 的输出。**

理由：

1. §十二.2 明令"不重新写 Agent"，§十二.5 明令"不制造新的数据库体系"。让每个 agent 都改成吐
   `TaskResult`，等于同时碰引擎和持久化。
2. 这个项目上一轮刚吃过教训：**先把实体建完、最后才发现执行路径没接上**（Agent 页从不走员工）。
   先改引擎协议再改界面，是同一个错误的重演。
3. `TaskResult` 需要的每一项**都已经在库里**：`status` 在 `build_runs`，`summary` 在
   `result_summary`，`artifacts` 在 `deliverables`，`verification` 在 `deliverables.verification`，
   `next_actions` 可从 `needs_approval` + 运行状态推，`memory_updates` 在 `memory_candidates`。
   一个投影层就能给出，且**没有第二份真相**。

唯一缺的是 `quality_score` —— 它是新的，且应由 §九 的类型化验收产出，不是编出来的。

## 5. 不修改范围

明确不做，避免范围蔓延。

| 不改 | 理由 |
|---|---|
| Agent 执行逻辑（`ai/agent/autonomous.py` 的循环、规划、恢复） | §十二.2 |
| 工具系统与权限判定核心（`ai/tools/permissions.py`） | 上一轮刚验证过，是安全边界 |
| RAG 管道（解析 / chunk / embedding / 检索） | 无用户可见缺陷指向它 |
| 数据库 schema | §十二.5。**本轮零迁移** |
| 打包 / 安装 / 签名链 | 上一轮刚验证通过 |
| 20 个页面的导航结构 | shell 验收 31 项锁定，动它要重验 |
| 引入 WebView / 复制 DeepSeek Bot 代码 | §十二.1 / §十二.6 |
| 造演示数据 | §十二.4。所有面板必须来自真实查询 |
